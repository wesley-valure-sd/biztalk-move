HL7 Web API

Cloud9.HL7.WebAPI has two controllers: IncomingMessagesController (partners post HL7 messages) and LocationController. Partners authenticate with a user name and password that the BLL checks against a partner database. Messages go to BTS.IncomingMessage. BizTalk polls that table (HL7SQLReceive).

Shared mechanisms

  1. Practice routing. Every flow that writes to a practice database finds the address in BTS.PracticeConfig. Dynamic WCF-SQL send ports carry the address at run time.
  2. Typed procedure calls. Each call uses a WCF-SQL schema from Cloud9.BizTalk.Schemas. The action is TypedProcedure/BTS/<ProcName>. Orchestrations set useAmbientTransaction=false and EnableTransaction=false. The procedures own the transactions.
  3. Process scheduling. Rows in BTS.ProcessParameter trigger the polling receive locations (ProcessClaims, ProcessCHCInboundFiles, ProcessTreatmentCards). BTS.QueueProcessParameters returns the practice list. The controller orchestration calls a worker for each practice.
  4. Logging. Central BTS.Log (through Common.AddLog), practice ImportLog (through BTS.AddImportLog), and the Windows event log.
  5. Configuration. The BizTalk Deployment Framework replaces ${...} placeholders in PortBindingsMaster.xml with values from SettingsFileGenerator.xml for each environment. Environments in the EDI settings: Default, Local Dev, JGLISSON Development, LAB, LAB2, LAB3, C9Prod1, C9Prod2, SDLab1, SDProd1. Some runtime settings (PDS API) come from SSO through SSOClientHelper.

Shared receive behavior

All 835 receive locations use the pipeline Cloud9.BizTalk.X12.Pipelines.ReceiveEDIPipeline (ReceiveEDIPipeline.btp).

  1. Archive component (decode stage). Class Cloud9.BizTalk.Shared.Components.Archive.Archive (Archive.cs). The binding sets FilePath to <receive folder>\Archive and FileName to %FileReceivedFileName%%FileReceivedFileExtension%. The component writes a copy of the raw file before parsing. Overwrite is true.
  2. EDI disassembler (disassemble stage). EdiDataValidation is true. XmlSchemaValidation is false. PreserveInterchange is false. Thus BizTalk publishes one message for each ST/SE transaction set. Each orchestration instance processes one transaction set, not one file.

  • Files arrive through the whole day. Most files arrive near 06:00 Eastern.

Practice resolution

Each posting flow must find the practice database. BizTalk uses the central table BTS.PracticeConfig (PracticeConfig.sql).

  1. The flow gets a practice name.
    • Flows A, B, C: the name of the folder that contains the file. The code takes BTS.InboundTransportLocation, removes the text after the last \ (FILE) or / (SFTP or FTP), and keeps the last path segment. For ...\Patient\GULFCOAST\*.* the name is GULFCOAST. For .../SD-GULFCOAST/*.* the name is SD-GULFCOAST.
    • Flow D: the text of FILE.ReceivedFileName after the last \ and before the first _. The CHC mailbox worker writes file names as <pcName>_<GUID>.edi.
  2. The flow calls BTS.GetPracticeConfigurationByName(@pcName NVARCHAR(50)). The procedure returns pcGUID, pcInstanceAddress, pcInstanceConnectionString for the row where pcName = @pcName. The procedure does not filter on pcsStatusID.
  3. The flow uses pcInstanceAddress as the WCF-SQL address of the dynamic send port. The value has the form mssql://<server>/<instance>/<database>? (inferred from the adapter type).

Flows A, B and C do not check for an empty result. If no row matches, the send to an empty address fails, the exception goes to the event log, and nothing is posted. Flow D checks for an empty address for each claim (see flow D).

Flow A: BBVA patient lockbox 835

Source: Process_BBVA_835Patient.odx (XLANG code starts at line 556).

Steps

  1. Activate on ReceiveBBVA835PatientPort. The logical port binds to RP_BBVA835_Patient. The message type is BBVA835_MMT (schema Cloud9.BizTalk.X12.Schemas.BBVA_X12_00501_835).
  2. Get the practice name from the folder. Call GetPracticeConfigurationByName through the static send port SP_BizTalkCloud9Common_WCF.
  3. Transform the 835 with BBVA_835Patient_To_ClaimPaymentBatchCanonical. The result has one ClaimPayment for each 2100 (CLP) loop.
  4. For each ClaimPayment (positional XPath //*[local-name()='ClaimPayment'][n]):
    1. Transform with ClaimPaymentCanonical_To_Post835PatientTransaction.
    2. Set lbcLockboxCodeType to PATIENT. The map writes the placeholder setme first.
    3. Send to the dynamic port with WCF.Action = TypedProcedure/BTS/Post835PatientTransaction, useAmbientTransaction=false, EnableTransaction=false, RetryCount=0.
    4. Read ErrorCount and ResponseMessage from the first result set.
    5. If ErrorCount != "0", write the message to the event log BizTalk.Process_BBVA_835Patient. Set log level 0 and state Failed. Else set log level 2 and state Finished. The log message is ResponseMessage in both cases.
    6. Call BTS.AddImportLog in the same practice database. See ImportLog rows.
  5. Catch System.Exception: write ex.ToString() to the event log only. No ImportLog row, no suspend. The remaining payments in the transaction set are not processed.

GetLockboxNumber(lockboxCode, checkDate) removes the checkDate text from the lockbox code and removes one trailing _.

public string GetLockboxNumber(string lockboxCode, string checkDate)
{
    if (lockboxCode.Contains(checkDate)) lockboxCode = lockboxCode.Replace(checkDate, System.String.Empty);
    if (lockboxCode.EndsWith("_")) lockboxCode = lockboxCode.Substring(0, lockboxCode.Length - 1);

Design notes:

  1. Idempotency. Store a hash of each raw file and each ST transaction set. Skip a set that is already done. BizTalk posts again if the same file arrives twice, unless the procedure rejects it.
  2. Unit of work. BizTalk posts one payment at a time and continues after an ErrorCount failure. Keep this behavior at first, so that the Cloud9 data matches. Record the result of each payment so that a rerun can skip the posted ones.
  3. Practice resolution. Make the folder-to-practice map explicit in configuration, or keep the lookup by pcName. Fail the file and alert if no practice matches.
  4. Configuration. Move every ${...} value to the new configuration store. Keep secrets in a vault. The settings file in this repository holds secrets in plain text (see document 05).
  5. Parsing library. Use an X12 005010X221A1 parser that keeps the custom BBVA qualifiers (REF*LB, REF*EJ, REF*69). The SD web files use the same segments with non-standard REF qualifiers (2H, 1Z, TN, 8X, EY, EM, TD).
  6. Dates. BizTalk sets transDateTime and transDateTimePosted to the processing time, not BPR16 or DTM02. Keep this unless the business asks for a change. The server time zone matters. The BizTalk server time is the current reference.
  7. Logging. Keep ilProcess values the same (Process_BBVA_835Patient, Process_SD_835Patient, Process_BBVA_835Insurance, Process_CHC_835Insurance), or agree new values with the Cloud9 team.
  8. Identity. Use a managed identity for the databases and a vault for the SFTP keys. Do not reuse the c9\svc.biztalk.host account.
  9. EDI tolerance. Accept ^ in ISA11. Accept $0.00 in CLP04 and in service-line amounts. Do not reject a payment with an unknown patGUID or pipGUID. The procedure sends it to the unmapped transactions.
  10. Observability. Give each file a correlation ID. Put the ID in every log line, Datadog event, and ImportLog row where a field exists.

4. Payment rules to implement (pseudo-code)

The code below restates the maps. The map summaries are the source of truth.

for each file:
    archive(file)
    for each ST transaction set in file:
        source  = BBVA_PATIENT | BBVA_INSURANCE | SD_WEB | CHC
        pcName  = folderName(file)                        # BBVA, SD (keeps "SD-")
                | fileName.afterLast('\').before('_')     # CHC
        practice = GetPracticeConfigurationByName(pcName)  # central DB

        case BBVA_PATIENT:
            lockbox = REF*LB.REF02.replace(DTM02, "").trimOneTrailing("_")
            note    = "Deposit Date: {DTM02}, Check Date: {BPR16}, Lockbox: {lockbox}"
            for each CLP loop:
                p = Post835PatientTransaction(
                      transGUID=newGuid, transStatus="N", transIsGroup="0",
                      transProductionAmount=0, transClaimAmount="0",
                      transAmount=transDueNowAmount=transTotalDueAmount = -CLP04,
                      transDateTime=now, transDateTimePosted=now,
                      patGUID=NM1*QC.NM109, ppGUID=NM1*IL.NM109,
                      transRouting=BPR07, transReference=TRN02, transCheckNumber=TRN02,
                      lbcLockboxCode=BPR04, lbcLockboxCodeType="PATIENT",
                      PaymentIdentifier=REF*F8.REF02, transNote=note)
                AddImportLog(process="Process_BBVA_835Patient", ref=REF*F8.REF02, result=p)

        case SD_WEB:
            for each CLP loop:
                ref(q) = REF02 where REF01 == q inside the CLP loop
                type   = BPR04                      # CCC | ACH | REV
                note   = ACH: "{M/dd/yyyy} payment; Transaction ID = {ref(2H)}; Response = Check Submitted"
                         REV: "{M/dd/yyyy HH:mm:ss tt} - Web ACH Return - (${abs(CLP04):#.##}) Additional Info: {ref(2H)}"
                         CCC: "Approval Code={ref(1Z)}; Transaction ID={ref(2H)}"
                p = Post835PatientTransaction(
                      ...same constants and amounts as BBVA patient...,
                      patGUID=first NM1.NM109, ppGUID=NM1*IL.NM109,
                      lbcLockboxCode=type, lbcLockboxCodeType="WEB",
                      transApprovalCode=ref(1Z), transTransactionIDStr=ref(2H),
                      transCardNumber = type==CCC ? ref(TN) : null,
                      transCardType   = type==CCC ? ref(8X) : null,
                      transCheckNumber= type in (ACH,REV) ? ref(1Z) : null,
                      transRouting=ref(EY), xwebGUID=ref(EM),
                      transReference = len(ref(EY))>0 ? (type in (ACH,REV) ? ref(TN) : null) : (type==CCC ? ref(TN) : null),
                      transNote=note, transReceiptNote=note)
                AddImportLog(process="Process_SD_835Patient", message = ok ? "Processed successfully" : p.ResponseMessage)

        case BBVA_INSURANCE:
            clp = count(LX loops); plb = count(PLB)
            if not (clp == 1 or plb == 0):
                AddImportLog(Failed, "There were {clp} CLP payments and {plb} PLB adjustments on transaction {ST02}")
                continue
            base = "Deposit Date: {DTM02}, Check Date: {BPR16}, Claim Number: {CLP01}, Lockbox: {lockbox}"
            for each CLP loop:
                note = BPR04 == "NON"
                       ? left(base + ", " + casList(claim CAS) + ", " + casList(service CAS), 250)
                       : base                      # casList = "CAS02: CAS03" joined by ", " (first pair only)
                p = Post835InsuranceTransaction(
                      constants as above, amount = -CLP04,
                      patGUID=REF*EJ, pipGUID=REF*69, pipPolicyNumber=NM1*QC.NM109,
                      adaClaimNumber=CLP01, ptPaymentTypeCode=BPR04, transRouting=BPR07,
                      transCheckNumber=TRN02, transReference=TRN02, ClaimIdentifier=TRN04,
                      PaymentIdentifier=REF*F8, transNote=note, transReceiptNote=note)
                AddImportLog(process="Process_BBVA_835Insurance", ref=REF*F8, result=p)
            n = 0
            for each PLB:
                n += 1
                p = Post835InsuranceTransaction(
                      constants, amount = PLB04 (map negates twice),
                      AdjustmentType=PLB03-1, transReference="ADJ{n}-{TRN02}",
                      patient/policy/claim fields from the single CLP loop,
                      transNote = base + ", Adj Reason: {PLB03-1}")
                AddImportLog(process="Process_BBVA_835Insurance", message="ADJ - " + p.ResponseMessage)

        case CHC:
            for each CLP loop:
                claim = int(CLP01.substring(12))          # fail the set if this does not parse
                reversal = CLP04 < 0 or CLP02 == "22" or any(service CAS01 contains "CR")
                if reversal:
                    AddTodoItem(adaclaimNumber=claim, message="Payment for claim{claim} needs reversal for amount ${CLP04}.")
                elif practice is null:
                    BTS.Log("Connection String not found for Claim {claim} in File {file}")
                    continue                               # no ImportLog row
                else:
                    p = Post835InsuranceTransaction(
                          constants, amount=-CLP04, adaClaimNumber=claim,
                          pipPolicyNumber=NM1*QC.NM109, ptPaymentTypeCode=BPR04,
                          transRouting=BPR07, transCheckNumber=TRN02,
                          transNote = transReceiptNote = "Check Number: {TRN02}, Claim Number: {claim}")
                AddImportLog(process="Process_CHC_835Insurance", message = ok ? "Processed successfully" : error)

Rules for the edge cases:

  1. Comparisons. The functoid names for <, OR, Find, Left, Size, Subtraction, Multiplication are inferred from their inputs. Confirm with a sample file and the BizTalk output before you rely on them.
  2. Multiple links to one field. In the BBVA insurance map, pipGUID gets values from three links. Test with real files to see which value BizTalk sends.
  3. Missing segments. BizTalk sends no element when the source segment is missing. The procedure then uses its default. Do the same: omit the parameter, do not send an empty string for a GUID.

5. Cut-over plan

  1. Read-only shadow run. Run the new application on copies of the production files. Do not post. Compare each computed parameter set with the BizTalk tracking data (message body tracking is on for Process_CHC_835Insurance only). For the other flows, compare with the [Transaction] rows and ImportLog rows.
  2. Test database run. Post to a test practice database. The discovery names Cloud9 T for this comparison. The settings also have an SDLab1 environment. Use the test-file scripts in Cloud9.BizTalk.Scripts to build files with real GUIDs. If necessary, restore the test BizTalk instance. Then run the same 835 files through BizTalk and the new application and compare the results.
  3. Switch one source at a time. For each source and region:
    1. Disable the BizTalk receive locations for that source (FILE and SFTP).
    2. Enable the new poller for the same folders.
    3. Watch ImportLog and the alert channel for one full business cycle.
  4. Keep BizTalk for rollback. Do not undeploy the orchestrations until every source runs on the new application for an agreed period.
  5. CHC last. The CHC flow shares the CHC_Inbound folder with the 277 and 277CA flows. If the new application takes over the mailbox download, it must also feed the 277 files to BizTalk (or replace those flows too). Else the claim status flows stop.
  6. Retire with evidence. Before you disable a legacy folder, port, or service, agree an observation period. Show zero traffic for that period.

Read the live procedure signatures

Run this query in one practice database (read-only). For production, use only the approved read-only endpoint.

SELECT  OBJECT_SCHEMA_NAME(p.object_id) AS SchemaName,
        OBJECT_NAME(p.object_id)        AS ProcName,
        p.parameter_id,
        p.name                          AS ParameterName,
        TYPE_NAME(p.user_type_id)       AS TypeName,
        p.max_length,
        p.is_output,
        p.has_default_value
FROM    sys.parameters AS p
WHERE   OBJECT_SCHEMA_NAME(p.object_id) = 'BTS'
  AND   OBJECT_NAME(p.object_id) IN ('Post835PatientTransaction', 'Post835InsuranceTransaction', 'AddImportLog', 'AddTodoItem', 'GetPracticeEDISettings')
ORDER BY ProcName, p.parameter_id;

-- Table-valued parameter type used by the insurance map (if it exists)
SELECT  tt.name AS TypeName, c.column_id, c.name AS ColumnName, TYPE_NAME(c.user_type_id) AS ColumnType, c.max_length
FROM    sys.table_types AS tt
JOIN    sys.columns AS c ON c.object_id = tt.type_table_object_id
WHERE   tt.name LIKE '%835%'
ORDER BY tt.name, c.column_id;

-- Procedure bodies
SELECT OBJECT_NAME(object_id) AS ProcName, definition
FROM   sys.sql_modules
WHERE  OBJECT_NAME(object_id) IN ('Post835PatientTransaction', 'Post835InsuranceTransaction', 'AddImportLog', 'AddTodoItem');
